# gsvg v1.1.0 Roadmap

## 1. Ellipse missing `rx()`/`ry()` setters

**Location:** `Ellipse.groovy:88-104`

Ellipse has getters (`getRx()`, `getRy()`) but no fluent setters. Users must fall back to
`addAttribute('rx', value)`, unlike every other shape which has fluent setters for all its
geometry attributes. Circle has `r(Number)` and `r(String)` -- Ellipse should mirror this
for `rx` and `ry`.

**Fix:** Add `rx(Number)`, `rx(String)`, `ry(Number)`, `ry(String)` methods returning
`Ellipse` for chaining.

## 2. Marker methods only on Line

**Location:** `Line.groovy:160-189`

`markerStart()`, `markerEnd()` are defined on `Line` only. Per the SVG spec, `marker-start`,
`marker-mid`, and `marker-end` apply to all shape elements (Path, Polyline, Polygon). These
belong on `AbstractShape` so all shapes can use them.

**Fix:** Move `markerStart()`, `markerEnd()` from `Line` to `AbstractShape` and add
`markerMid()`.

## 3. `addPolyline(String points)` missing

**Location:** `AbstractElementContainer.groovy`

`addPolygon(String points)` exists (line 361) but there is no `addPolyline(String points)`.
`AbstractPoly` already has `points(String)`, so the only gap is the factory overload.
Inconsistent -- users who discover the Polygon variant will expect the same for Polyline.

**Fix:** Add `addPolyline(String points)` factory method on `AbstractElementContainer`.

## 4. No `addPolyline()` / `addPolygon()` no-arg factories

**Location:** `AbstractElementContainer.groovy`

All other shapes have a no-arg factory (`addCircle()`, `addRect()`, `addPath()`, etc.) but
Polyline and Polygon only offer `Coordinate...`, `List<Number>...`, `Map`, or `Closure`
variants.

**Fix:** Add `addPolyline()` and `addPolygon()` no-arg factory methods.

## 5. Missing convenience factory overloads for common shapes

**Location:** `AbstractElementContainer.groovy`

- No `addCircle(Number cx, Number cy, Number r)` -- must chain `.cx().cy().r()`
- No `addEllipse(Number cx, Number cy, Number rx, Number ry)`
- No `addRect(Number x, Number y, Number width, Number height)` -- only `addRect(width, height)` exists

These are the most commonly used shapes; one-liner construction would improve ergonomics.

**Fix:** Add the overloads listed above.

## 6. `addPath(String)` sets id, not path data

**Location:** `AbstractElementContainer.groovy:338-339`

`addPath(String)` sets the `id` attribute, not `d`. There is no way to do
`addPath("M0,0 L10,10")` -- users must always call `addPath().d(...)` separately.

**Fix:** Add an `addPathData(String d)` factory method (or similar) that creates a Path
and sets its `d` attribute.

## 7. Text does not extend AbstractShape

**Location:** `Text.groovy:10`

Text extends `StringContentContainer` -> `SvgElement`, not `AbstractShape`. This means it
is missing: `stroke()`, `strokeWidth()`, `opacity()`, `transform()` convenience methods,
and the `fill(Color)` overload. Per the SVG spec, text elements support all presentation
attributes.

**Fix:** This is the largest structural change. Options include making Text extend
AbstractShape, introducing a shared trait/mixin for presentation attributes, or adding
the missing methods directly to Text. Needs design consideration.

## 8. No `toSvgFile(Svg, OutputStream)` overload

**Location:** `SvgRenderer.groovy`

The File variant exists but there is no stream variant, unlike PNG and JPEG which both
have File and OutputStream overloads.

**Fix:** Add `toSvgFile(Svg, OutputStream)`.

## 9. `RendererOptionsBuilder.toMap()` not discoverable

**Location:** `RendererOptionsBuilder.groovy`

The `toMap()` method exists but is not mentioned in the class-level Javadoc, making it
hard to discover.

**Fix:** Mention `toMap()` / `build()` in the class-level documentation.

## 10. `@CompileStatic` coverage

**Location:** `gsvg-core` (all classes), `gsvg-export` (partial)

gsvg-core already annotates all 136 classes with `@CompileStatic`. The project-wide
config script approach was attempted but it also applies to test code, causing 70
compilation errors in tests that use dynamic Groovy features. Splitting compile/compileTests
into separate executions with different configs is a future improvement.

**Done:** Added `@CompileStatic` to `RendererOptionsBuilder` in gsvg-export. The other
4 export classes (SvgRenderer, SvgOptimizer, SvgFormatter, SvgResizer) use dynamic Groovy
patterns (regex matcher indexing, Map closures) that require refactoring for static
compilation — deferred to a future release.

## 11. GroovyDoc coverage for all public API

Audit all public classes and methods across `gsvg-core` and `gsvg-export` to ensure every
public class, method, and constructor has GroovyDoc. Focus especially on any new methods
added as part of this release (items 1-8) and any existing gaps.

**Fix:** Add missing GroovyDoc to all public classes and methods. Each should include a
description, `@param`, `@return`, and `@throws` tags where applicable.

## 12. Update README.md

Update the project README to reflect all new features and API changes introduced in v1.1.0.
This includes documenting new factory overloads, Ellipse setters, marker support on all
shapes, OutputStream overloads, and any other user-facing changes.

**Fix:** Review each item in this roadmap and ensure the README examples and feature
descriptions are up to date.

## 13. Update and expand gsvg-examples

Update the `gsvg-examples` module to cover all new features added in v1.1.0. Add new
example files or extend existing ones to demonstrate:
- Ellipse `rx()`/`ry()` setters
- Marker usage on Path, Polyline, Polygon
- New factory overloads (`addCircle(cx,cy,r)`, `addPolyline(String)`, etc.)
- `addPathData(String)` convenience method
- `toJpeg` and `toSvgFile` OutputStream overloads
- Any other new features

**Fix:** Add or update examples in `gsvg-examples/src/main/groovy/examples/`.
